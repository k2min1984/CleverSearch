## 3. 핵심 결정과 근거

### 3.1 `dbsources.html` — "증분 색인 설정" 섹션 분리

기존 폼은 3-칸 grid 한 줄(대상볼륨/제목컬럼/청크크기)이 마지막이었다. 신규 3 필드를 같은 grid 에 그냥 끼워넣으면 폼 길이가 한 화면을 벗어나고, **이 3 필드가 LEGACY 동기화에는 선택이고 워커 색인에는 필수** 라는 의미 차이가 시각적으로 드러나지 않는다.

→ `border + bg-gray-900/40` 의 별도 박스로 묶고, 헤더에 다음을 명시:

```html
<span class="text-sm font-bold text-amber-300">⚙ 증분 색인 설정</span>
<span class="text-xs text-gray-400">— 워커 색인(enqueue) 사용 시 3개 필드 모두 필수, LEGACY 동기화에는 선택</span>
```

이렇게 하면 운영자가 "이게 뭐지?" 라는 질문 없이도 의미를 파악 가능. 각 input 아래 `[11px] text-gray-500` 으로 짧은 보조 설명도 추가:
- cursor_column: "외부 DB에 인덱스 필수. 영문/숫자/밑줄만"
- pk_column: "OpenSearch 문서 _id 생성용"

설계서 §9 "운영상 주의사항 3 — cursor_column 인덱스" 를 UI 에서 미리 알려준다.

### 3.2 카드의 "워커 색인" 버튼 disabled 처리 — UI 가 백엔드 검증을 흉내내지 않게

DB 카드의 워커 색인 버튼은 `cursor_column && cursor_type && pk_column` 셋 다 채워졌을 때만 활성화. 그렇지 않으면 `disabled` + opacity-40 + tooltip 으로 사유 안내.

**왜 disabled 까지 가는가?** — 백엔드 `enqueue_sync_job()` 도 같은 검증을 하므로 호출해도 실패만 나는데, 사용자가 클릭한 뒤 alert 받는 흐름은 짜증을 유발한다. UI 단계에서 차단하되 **백엔드 검증을 무력화하는 클라이언트-side 로직은 만들지 않는다** (즉, 버튼만 disabled, payload 검증은 안 함). 이중 검증 — 신뢰는 백엔드.

SMB 카드는 disabled 처리를 안 했다 — SMB/SSH enqueue 는 cursor 사전 설정 없이도 첫 실행이 가능하기 때문(설계서 §5.4: cursor_value 빈 상태로 시작).

### 3.3 카드 grid 4→5 칸 vs 별도 액션 행

기존 4 버튼(접속 테스트 / 동기화 / 수정 / 이력) 옆에 "워커 색인" 을 추가해야 하는데:

- **선택 A**: grid 4→5 칸으로 늘림 → 구현 1줄 변경, 컬럼이 살짝 좁아짐
- **선택 B**: 액션 행을 2줄로 분리 → 카드 높이 증가, 다른 카드와 정렬 어긋남

→ A 선택. 실제 카드 폭에서 5 버튼이 모두 한 줄에 들어가는 것을 확인. tooltip 으로 LEGACY/워커 차이 명시.

### 3.4 `confirm` 두 단계로 incremental/full 모드 선택

전용 dialog 컴포넌트가 없는 단순 admin UI 라서 native `confirm` 으로 처리. 한 번에 incremental/full 을 모두 시각화하기 어렵기 때문에:

```
1. confirm("증분 모드(incremental) 로 등록합니다.\n확인=incremental, 취소=모드 선택 창으로 이동")
   → OK 면 incremental 로 즉시 등록
   → Cancel 면 다음 단계로
2. confirm("⚠ 전체 재색인(full) 으로 등록하시겠습니까?")
   → OK 면 full 로 등록
   → Cancel 면 작업 중단
```

UX 가 화려하지는 않지만:
- 기본 경로(incremental) 가 한 번의 OK 로 끝난다 (가장 흔한 케이스)
- full 은 "정말?" 한 번 더 묻는 경고 — full 이 cursor 초기화로 외부 DB 재전수 SELECT 부담을 만들기 때문
- 추가 라이브러리/모달 의존성 없음

### 3.5 SyncJob 패널 위치 — `indexing.html` 상단

후보:
- **A**: `indexing.html` 상단에 새 섹션 (현재 선택)
- B: 별도 페이지 `sync-jobs.html` + 메뉴 항목 추가
- C: dashboard.html

→ A 선택. 이유:
- "색인 관리" 라는 의미 묶음이 자연스럽다 — Job 진행과 결과 이력은 같은 화면에서 보는 게 직관적.
- 기존 메뉴에 "통합 색인 이력" 이 이미 있고, 운영자가 색인 관련 정보를 찾을 때 첫 진입점이 된다.
- 별도 페이지를 만들면 메뉴 항목/네비게이션을 손대야 하는데, Phase 4 범위를 최소화하기 위해 메뉴 변경은 보류.

상단 → 하단 순서:
1. SyncJob 진행 패널 (실시간성)
2. 통합 색인 이력 (감사용 누적)

### 3.6 5초 자동 새로고침 토글 — 기본 off

진행 중인 Job 의 진행률을 사용자가 가만히 보고 싶을 때만 켜도록 default off. 켜면 5초 간격 `setInterval`. 이유:
- 대부분의 시간은 Job 이 없거나 종료된 상태 → 무의미한 폴링 부하
- 백엔드 `/sync-jobs` 쿼리는 가볍지만, 100명이 동시에 5초 폴링하면 작은 부하라도 누적
- "필요할 때 켠다" 가 운영자 의도와 맞다

**왜 WebSocket 이 아닌가?** — 인프라 단순함 우선. 현재 프로젝트에 WebSocket 어댑터가 없고, 5초 폴링으로 진행률을 보는 정도는 충분히 부드럽다.

### 3.7 진행률 바 표현 — `total_estimated` 가 NULL 이면 처리량만 표시

현재 백엔드는 `total_estimated` 를 채우지 않는다 (Phase 2/3 핸들러가 set 안 함). 그래서 패널은:

```js
if (total > 0) {
    // 진행률 바 + "X / Y (Z%)"
} else {
    // "X 처리" 만 표시 (바 없음)
}
```

**왜 total_estimated 채우지 않았나?** — 외부 DB 전수 COUNT 는 비싸고, SMB walk 도 처음 한 번 다 돌아야 총 개수가 나오므로 사전 산정이 의미 없다. 현실적으로 "현재까지 X 건 처리" 만 보여주는 게 정직하다. 운영 측정 후 의미 있는 추정치를 만들 수 있으면 추후 개선.

### 3.8 일시정지/재개 — viewer 권한 차단

`renderSyncJobs()` 내부에서 `loggedInRole === "viewer"` 면 컨트롤 버튼을 아예 렌더링 안 함. 백엔드도 `require_role("operator")` 로 막혀 있으므로 이중 보호. 일시정지 가능 상태(`pending`/`running`) 와 재개 가능 상태(`paused`) 를 status 별로 분기해 적절한 버튼만 노출.

### 3.9 `dbsources.html` 카드의 증분 정보 줄

기존 정보 grid 마지막 행에 `col-span-2` 한 줄 추가:

- 설정 완료: `✓ 사용 가능 · cursor=updated_at (datetime) · pk=id · 마지막=2026-04-27T...`
- 미설정: `⚠ 미설정 (cursor_column/cursor_type/pk_column 입력 필요)`

`last_cursor_value` 도 30자까지 잘라 표시 — 운영자가 마지막 색인 지점을 카드에서 바로 확인 가능. 카드 모달 열지 않고도 "이 소스 어디까지 색인됐지?" 를 알 수 있게.

## 4. UI 동선 정리

### 4.1 새 DB 소스를 워커 색인으로 운영하는 흐름

1. DB 소스 탭 → "+ DB 소스 등록" → 기본 정보 입력
2. **증분 색인 설정** 섹션 펼쳐 보고 cursor_column / cursor_type / pk_column 입력
3. 저장 → 카드에 `✓ 사용 가능` 뱃지 표시
4. 카드의 **워커 색인** 버튼 (활성 상태) 클릭
5. confirm "incremental 로 등록?" → OK
6. alert "Job ID 7 등록 완료"
7. 색인 관리 탭으로 이동 → SyncJob 패널 → "5초마다 자동 새로고침" 체크
8. 진행률 / 색인/스킵/실패 카운트 / cursor 실시간 갱신 확인

### 4.2 잘못 등록한 Job 멈추기

1. 색인 관리 탭 → SyncJob 패널 → 해당 row 의 **일시정지** 클릭
2. confirm → 백엔드 `paused` 처리, 패널 갱신
3. 필요시 source 설정 수정 후 같은 row 의 **재개** 클릭 → status=pending → 워커가 다시 가져감

### 4.3 LEGACY 와 워커 색인 공존

기존 **동기화** 버튼은 그대로 — 즉시 블로킹 처리. 작은 소스 / 즉시 결과가 필요할 때 사용.
**워커 색인** 버튼은 비동기 — 큰 소스 / 증분 / 체크포인트 재개가 필요할 때.

운영자가 둘 중 어느 걸 써야 할지 망설이지 않게 각 버튼 tooltip 에 명시:
- 동기화: "LEGACY 동기화 (즉시 블로킹)"
- 워커 색인: "워커 색인 (백그라운드, 증분 + 체크포인트)"
