## 0. 요약

1차 사이클에서 미반영된 후속 권고를 모두 반영. 추가 확보된 보안 영역은 다음과 같습니다:

| 항목 | 상태 |
|---|---|

| M-4 MFA(TOTP) 등록/검증 + admin 강제 정책 | ✅ |
| M-5 Audit Log 테이블 + 로그인/MFA/비밀번호 변경 기록 | ✅ |

## 2. 항목별 상세

### M-3. 비밀번호 정책 + 변경 API
**정책** ([config.py](../app/core/config.py))
- `AUTH_PW_MIN_LENGTH = 9` (국정원 가이드)
- `AUTH_PW_REQUIRE_CHARS_COUNT = 3` (영대/영소/숫자/특수 4종 중 3종 이상)
- `AUTH_PW_HISTORY_COUNT = 5` (직전 5개 재사용 차단)
- `AUTH_PW_MAX_AGE_DAYS = 90` (만료, 추후 연동)

**검증** ([database.py:validate_password_policy](../app/core/database.py))
```python
ok, msg = validate_password_policy("abc1!")          # → False, "최소 9자 이상…"
ok, msg = validate_password_policy("Strong#Pass99")  # → True, "ok"
ok, msg = validate_password_policy("admin#Pass99", username="admin")  # → False, "사용자 ID 포함"
```

**변경 API**
```
POST /api/v1/common/auth/password
  Authorization: Bearer <access>  (또는 cs_access_token cookie)
  { "current_password": "...", "new_password": "..." }
```
- 현재 비밀번호 검증 → 정책 검증 → 직전 N개 재사용 차단 → 동일 비번 차단
- 성공 시 `must_change_password=False`, `failed_login_count=0`, `locked_until=NULL`
- audit 로그 기록 (`password_change` / success|fail)

**must_change_password 흐름**
- 로그인 응답에 `must_change_password: bool` 포함 → 프런트가 강제 변경 화면 노출 (UX 추후 연결)

### M-4. MFA (TOTP)
**구현 방식**: 외부 의존성 추가 없이 RFC 4648 Base32 + RFC 6238 TOTP(SHA-1, 30s, 6 digits) 직접 구현. Google Authenticator, Authy, 1Password 등 표준 앱과 호환.

**API**
```
POST /api/v1/common/auth/mfa/enroll      → { secret, otpauth_url }
POST /api/v1/common/auth/mfa/confirm     → { secret, code } 검증 후 mfa_enabled=True 저장
POST /api/v1/common/auth/login           → { username, password, mfa_code }
```
- `MFA_REQUIRED_FOR_ADMIN=true` (기본): admin 권한은 mfa_enabled=True 인 경우 mfa_code 필수
- 일반 사용자도 mfa_enabled=True 면 mfa_code 필수
- TOTP drift ±30 초 (총 ±90초 윈도)
- 모든 단계 audit (`mfa_confirm`, `login_fail` with detail="mfa_invalid")

### M-5. Audit Log
**테이블**: [audit_logs](../app/core/database.py)
| 컬럼 | 설명 |
|---|---|
| occurred_at | 발생 시각 |
| actor / actor_role | 사용자 + 역할 (인증 전이면 NULL) |
| action | login_success, login_fail, password_change, mfa_confirm 등 |
| target | 대상 (대상 사용자명/리소스 ID) |
| status | success / fail / warn |
| ip, user_agent | 클라이언트 식별 |
| detail | 추가 정보 (JSON 등) |

**기록 시점** (현재 적용 분):
- 로그인 성공/실패
- MFA 확인
- 비밀번호 변경 (성공/실패/원인)

추후 권고: 사용자 추가/삭제, 권한 변경, 인덱스 삭제, 카드 신규등록 등 admin action 도 동일 테이블에 기록.

### M-6. HTTP → HTTPS 강제 redirect
[main.py](../app/main.py)
```python
if settings.FORCE_HTTPS_REDIRECT or settings.APP_ENV in {"prod", "production"}:
    app.add_middleware(HTTPSRedirectMiddleware)
```
- 운영 환경에서는 자동 활성화
- 개발 환경에서도 `FORCE_HTTPS_REDIRECT=true` 로 강제 가능
- 첫 요청부터 HTTP 평문 차단 (HSTS 와 결합)

### M-7. PII 마스킹
**모듈**: [app/common/pii.py](../app/common/pii.py)

| PII 종류 | 패턴 | 마스킹 결과 |
|---|---|---|
| 주민/외국인등록번호 | `\d{6}[-\s]?\d{7}` | `901231-*******` |
| 신용카드 | 13~19자리 | `4242-****-****-4242` |
| 휴대전화 | `01[016789]-?\d{3,4}-?\d{4}` | `010-****-5678` |
| 이메일 | `local@domain` | `h***@example.com` |
| 사업자등록번호 | `\d{3}-?\d{2}-?\d{5}` | `123-**-67890` |

**적용 지점**:
- [db_service.py:save_search_log](../app/services/db_service.py) — 검색 로그 저장 시
- [db_service.py:save_recent_search](../app/services/db_service.py) — 최근 검색 저장 시

**환경변수**: `PII_MASKING_ENABLED=true` (기본)

### L-3 / L-4. 에러 일반화 + print → logging
- `test_connection_url` 일반 예외 → "DB 연결 실패 — 접속 정보를 확인하세요"
- system_service.py self-heal print → `logger.warning(...)`
- main.py 정적 경로 미발견 print → `logging.getLogger(__name__).warning(...)`

### L-5. 역할별 토큰 만료
**기본값** ([config.py](../app/core/config.py)):
```env
JWT_ACCESS_MINUTES_ADMIN=60        # 1h
JWT_ACCESS_MINUTES_OPERATOR=240    # 4h
JWT_ACCESS_MINUTES_VIEWER=1440     # 24h
JWT_REFRESH_MINUTES_ADMIN=240      # 4h
JWT_REFRESH_MINUTES_OPERATOR=1440  # 24h
JWT_REFRESH_MINUTES_VIEWER=10080   # 7d
```

[security.py:create_access_token](../app/core/security.py) 가 `_access_minutes_for(role)` / `_refresh_minutes_for(role)` 분기로 역할별 만료 적용. 미설정 시 기존 `JWT_EXPIRE_MINUTES` / `JWT_REFRESH_EXPIRE_MINUTES` 폴백.

## 6. UI/UX 후속 권고 (별도 PR)

이번 PR 은 백엔드 인프라까지 완성. 운영 활용을 위해 프런트에 다음 화면이 필요합니다:
