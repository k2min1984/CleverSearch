# CleverSearch CS-53 스케줄러 버튼 오류 수정

## 증상과 원인

- 사용자 신고: 스케줄러 시작을 눌러도 화면 변화가 없고 콘솔 오류가 보임.
- 실제 브라우저 콘솔에서 `ReferenceError: showToast is not defined` 확인. `startScheduler`의 신규 시작/이미 실행 중 분기에서 발생.
- `static/admin/scheduler.html`이 정의되지 않은 `showToast`를 `showToast && showToast(...)`로 호출. 정의되지 않은 변수를 이렇게 읽어도 ReferenceError가 발생한다.
- 서버 요청 후 안내 메시지를 표시하는 부분에서 함수 실행이 멈추므로 뒤에 있는 `loadSchedulerStatus()`가 호출되지 않아 상태 표시가 갱신되지 않았다. 중지·설정 변경·삭제에도 동일 호출이 있었다.

## 수정한 내용

- 수정 파일: `C:\02.Project\01.파이썬\01.WorkSpace\CleverSearch\static\admin\scheduler.html`.
- 백업: `source-backups/scheduler-20260930-121620/scheduler.html`.
- 화면 안에 전용 메시지 영역과 `showSchedulerMessage()`를 추가. 공통 알림 함수 의존성을 제거하고 메시지는 textContent로 표시.
- 시작/중지 후 서버의 실제 상태를 다시 읽어 `실행 중`/`중지됨` 표시와 안내문을 갱신.
- API 요청 실패 시 실패 이유를 화면에 표시. 상태 조회 실패를 정상적인 중지 상태로 표시하지 않도록 수정.
- 주기 변경/삭제의 같은 오류도 수정. 설정 저장 실패 시 목록을 다시 읽어 표시를 복원.
- 화면 파일 수정으로 반영되므로 서버 재시작이나 DB 구조 변경은 하지 않음.

## 실제 검증

| 확인한 동작 | 결과 |
|---|---|
| 수정 전 서버 상태 및 시험 소스 설정 조회 | 중지, 24시간, 소스 활성 상태 |
| 스케줄러 시작 클릭 | `● 실행 중`, `스케줄러가 실행 중입니다.` 표시 |
| 실행 중 다시 시작 클릭 | 실행 상태 유지, 콘솔 오류 없음 |
| 스케줄러 중지 클릭 | `● 중지됨`, `스케줄러가 중지되었습니다.` 표시 |
| 시험 소스 주기를 24시간에서 1시간으로 변경 | 저장 후 다시 읽은 목록에서 1시간 표시, 설정 변경 안내 표시 |
| 원래 24시간으로 복원 | 서버 조회에서 1440분 확인 |
| 마지막 브라우저 콘솔 확인 | 오류 목록 0개 |
| JavaScript 구문 검사 | Node `--check` 통과 |

최종 HTTP 조회로 스케줄러 중지 상태, 소스 활성 여부, 24시간 주기, 다음 실행 시각, 소스별 마지막 실행 값이 작업 전과 일치하는지 확인했다. 주기 변경/복원에 따라 설정의 updated_at과 스케줄러 자체의 마지막 확인 시각은 갱신됐다.

증거: `scheduler-before.json`, `scheduler-after.json`, `scheduler-ui-check.js`. 실제 버튼 검증은 별도 임시 탭에서 수행하고 완료 후 닫았다. 사용자 수동 시험 결과표는 변경하지 않았다.

## 범위와 실행 중 이슈

- 시작·중지·재시작 클릭·주기 변경/복원을 실제 브라우저에서 확인했다. 스케줄 삭제는 실행하지 않았다.
- 시험 소스의 다음 실행 시각이 미래여서 이번 시작/중지 검증 중 자동 문서 동기화는 실행되지 않았다. 이 결과를 장시간 예약 실행 시험 통과로 표현하지 않는다.
- 처음 읽기 전용 검사에 사용한 번들 Python에는 requests가 없어, 표준 라이브러리 urllib로 상태 조회를 수행했다. 앱 서버 장애가 아니다.
- 사용자 오류 수정 요청과 기존 기록 위임 범위에서 수정. 프로젝트 파일 쓰기는 도구의 자동 승인 검토 허용 후 실행했으며 실제 사용자 승인 버튼 클릭으로 기록하지 않는다.
