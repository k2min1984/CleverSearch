### CS-50 쉬운 설명

이 시험은 **등록한 폴더 안의 문서를 검색할 수 있게 처리하고, 그 일이 끝났는지 확인하는 것**이다.

1. CS-49에서 만든 `수동검증_로컬폴더_20261001` 이름이 적힌 상자를 찾는다. 이것을 앞에서는 “테스트 소스 카드”라고 불렀다.
2. 그 상자의 **동기화**를 누른다.
3. 처음 뜨는 안내창에서 **확인**을 누른다. 이것이 **증분 모드** 선택이다. “증분 모드”라는 별도 버튼을 찾을 필요 없다. 앞서 처리한 지점부터 이어서 확인하는 방식이다. 이 화면의 **취소**는 작업을 바로 끝내는 것이 아니라 전체 재색인 여부를 묻는 다음 창으로 넘어간다. 잘못 넘어갔다면 그 두 번째 창에서 **취소**한다.
4. 접수 안내창의 `Job ID` 숫자를 메모한다. 이것은 이번 작업에 붙인 접수번호다. 알림의 **확인**을 눌러 닫는다.
5. 왼쪽 메뉴의 **통합 색인 이력**을 누른다. 화면에 조회 버튼이 두 개 있으므로 **맨 위의 조회**를 누른다.
6. 맨 위 표의 `ID`에서 메모한 접수번호를 찾고 `상태`를 읽는다. `소스ID`는 폴더의 번호이며 작업 접수번호와 다르다.

| 상태 표시 | 쉬운 뜻 | 어떻게 하면 되나 |
|---|---|---|
| `pending` | 차례를 기다리는 중 | **5초마다 자동 새로고침**을 체크하고 기다린다. |
| `running` | 문서를 처리하는 중 | 완료될 때까지 상태를 확인한다. |
| `done` | 작업이 끝남 | 같은 행의 `색인/스킵/실패`에서 마지막 실패 건수가 0인지 확인한다. |
| `failed` | 오류 때문에 작업이 실패함 | 표시된 오류 문구와 Job ID를 기록한다. |

작은 폴더는 빨리 끝나므로 대기와 실행 중 화면을 못 보고 바로 완료가 보여도 정상이다. 이미 등록된 문서를 건너뛰어 `스킵` 숫자가 올라가는 것도 정상이다. 반대로 접수 안내 알림만 뜨거나 계속 대기 중인 상태는 아직 처리 완료로 기록하지 않는다. 확인이 끝나면 켰던 자동 새로고침 체크를 해제한다.

| CS-X03 | 테스트 소스의 파일 감시를 켠 상태에서 **04_폴더수집용**에 새 지원 문서를 넣고 본문 수정 후 저장한다. | 새 내용 검색 가능, 수정 내용 반영, 관련 이력 확인. 원본 파일 이동/수정은 탐색기·문서 편집기가 필요하므로 웹 클릭만으로는 전 단계를 수행할 수 없다. 감시를 중지하고 시험 파일을 정리한다. |
| CS-X04 | 기본 인덱스와 구분되는 빈 시험 볼륨으로만 수행. **볼륨 관리** → 인덱스 `manual-test-20261001`, 샤드 1, 복제 0 → **볼륨 생성 → 목록 새로고침** → 시험 행 **수정**에서 Alias 변경·저장 → 시험 행 **삭제**. | 생성/수정이 유지되고 빈 시험 볼륨만 삭제된다. 기본 인덱스와 DB 소스가 사용하는 볼륨의 삭제 보호는 별도 개발자 시험으로 확인한다. 기존 데이터가 있는 볼륨은 대상으로 삼지 않는다. |
| CS-X05 | 모든 기본 시험 종료 후, 별도 초기화용 DB/인덱스와 복원 절차가 준비됐을 때만 **초기화 → 전체 데이터 초기화**, 이어 별도 환경에서 **인덱스 완전 삭제 + DB 초기화**. | 안내한 범위만 비워지고 다시 업로드·검색할 수 있어야 한다. 지금 사용 중인 로컬 자료를 보존하려면 실제 실행은 보류. |
| CS-X06 | 시험용 인증서와 갱신 방법 준비 → **SSL 관리 → 갱신 스크립트 생성** 내용을 검토 → 준비된 시험 환경에서 **갱신 스크립트 실행** → **인증서 상태** 재조회. | 실행 성공·유효기간 갱신을 확인. 기존 로컬 HTTP 화면 확인과는 별도 시험. 준비 없으면 보류. |
| CS-X07 | 충분한 시험 문서를 준비해 검색 결과를 20건보다 많게 만든다 → 결과 페이지 **다음 → 이전**, 카테고리·파일 필터 적용. | 페이지 간 누락/중복 없이 이동하고 첫·마지막 페이지 이동 버튼 상태가 맞는다. 기본 5종으로는 페이지 이동을 전부 시험할 수 없다. |
| CS-X08 | **대시보드 → 스모크 실행**은 자동 점검 범위와 시험 데이터 영향을 확인한 후 별도 시험 환경에서 실행한다. | 항목별 결과와 실패 사유가 표시된다. 화면 진단용 **디버그** 출력도 읽을 수 있다. 버튼이 자동 시험을 시작하므로 단순 메뉴 열기와 구분해 결과 기록. |

### 웹 시험과 별개로 남기는 항목

- 사용자 검색 결과의 `⋮`는 현재 별도 동작이 없는 표시다. 클릭 가능한 작업 메뉴 완성 여부는 개선 사항으로 남긴다.
- 가중치 **초기값 복원**은 사용자 지정 값을 모두 기본값으로 바꾼다. CS-42는 원래값을 직접 재입력하여 시험 상태를 보존한다. 기본값 복원 자체를 시험하려면 먼저 모든 값을 기록한 후 실행하고 사용자 값을 다시 저장한다.
- 네트워크/통합 색인 이력의 **이력 정리**는 이전 기록을 삭제한다. 별도 폐기 가능한 시험 기록이 없으면 삭제 실행은 보류한다.
- MFA·실제 TLS·보안 토큰 위조·20개/200MB API 제한·대량/장시간 시험은 웹의 정상 클릭만으로 충분히 확인되지 않는다. 기존 개발자 자동 시험 결과와 운영 환경 시험을 함께 판단한다.
