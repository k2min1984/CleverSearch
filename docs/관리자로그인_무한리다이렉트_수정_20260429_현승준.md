# 관리자 로그인 화면 깜빡임(무한 리다이렉트) 수정

작성일: 2026-04-29
작성자: 현승준
관련 파일: [static/admin/login.html](../static/admin/login.html), [static/admin/index.html](../static/admin/index.html)

---

## 1. 증상

관리자 로그인 직후 또는 /admin 재진입 시 화면이 빠르게 깜빡거리며(와리가리) 정상 진입이 안 되는 케이스가 발생.

- 정상 동작: `/admin#dashboard` 가 그대로 표시됨
- 비정상 동작: `/admin` ↔ `/static/admin/login.html` 이 빠르게 왕복하며 화면이 깜빡거림

---

## 2. 원인 분석

### 2.1 인증 메커니즘 이중화 — localStorage(토큰 문자열) + 쿠키(`cs_access_token`)

[app/api/common/auth.py](../app/api/common/auth.py) 의 `/login` 응답이 **HttpOnly 쿠키**(`cs_access_token`, `cs_refresh_token`)를 설정한다. 동시에 [login.html](../static/admin/login.html) 은 응답 JSON 의 `access_token` / `refresh_token` 을 **localStorage** 에도 저장한다.

→ **인증 상태의 진실 소스가 둘**(쿠키 vs localStorage)이며, 둘이 어긋나면 문제 발생.

### 2.2 무한 리다이렉트 루프

수정 전 코드:

[login.html](../static/admin/login.html) (수정 전)
```js
const existingToken = localStorage.getItem("cleversearch_admin_token") || "";
if (existingToken) {
    window.location.replace("/admin");   // ← 토큰 유효성 검증 없이 이동
}
```

[index.html](../static/admin/index.html) (수정 전)
```js
function forceLoginRedirect() {
    window.location.replace("/static/admin/login.html");
    // ← localStorage 토큰을 정리하지 않음
}

async function logoutJwt() {
    // ...
    localStorage.removeItem("cleversearch_admin_username");
    localStorage.removeItem("cleversearch_admin_role");
    localStorage.removeItem("cleversearch_admin_active_tab");
    localStorage.removeItem("cleversearch_admin_force_dashboard_once");
    // ❌ "cleversearch_admin_token" / "cleversearch_admin_refresh_token" 누락
    forceLoginRedirect();
}
```

→ 다음 시나리오에서 무한루프:

```
[t=0]  쿠키 만료/유실 (브라우저 정리, 시크릿 모드, 시간 경과 등)
       localStorage 토큰은 살아있음
[t=1]  /admin 진입
[t=2]  initializeSession() → /api/v1/common/auth/me  → 401 (쿠키 없음)
[t=3]  forceLoginRedirect() → /static/admin/login.html
       (이때 localStorage 토큰 제거 안 됨 ← 첫 번째 버그)
[t=4]  login.html 진입 → existingToken 있음 → /admin 으로 redirect
       (이때 /me 검증 없이 토큰 존재만 보고 이동 ← 두 번째 버그)
[t=5]  /admin → /me 401 → forceLoginRedirect → ... 반복
```

브라우저가 빠르게 두 페이지를 왕복하며 깜빡임이 발생함.

### 2.3 쿠키와 localStorage 가 어긋나는 실제 케이스

- 쿠키만 만료(JWT_EXPIRE_MINUTES 경과 후)
- 사용자가 브라우저 쿠키만 삭제 / 시크릿 모드로 전환
- HTTPS / HTTP 혼용 (secure 쿠키가 다른 스킴에선 안 보냄)
- 인증서 변경으로 secure 쿠키 거부
- 동일 도메인의 다른 포트에서 로그인 (쿠키 도메인 스코프 차이)
- 백엔드가 토큰을 폐기(blacklist)했는데 클라이언트는 모름

## 3. 수정 사항

### 3.1 [static/admin/login.html](../static/admin/login.html) — 자동 리다이렉트 시 /me 로 실제 검증

수정 후:
```js
(function autoRedirectIfAuthenticated() {
    const existingToken = localStorage.getItem("cleversearch_admin_token") || "";
    if (!existingToken) return;

    fetch(`${AUTH_API}/me`, {
        method: "GET",
        credentials: "include",
        cache: "no-store"
    }).then((res) => {
        if (res.ok) {
            window.location.replace("/admin");
        } else {
            // 쿠키 누락/만료 → 잔존 localStorage 토큰을 정리해 무한루프 차단
            localStorage.removeItem("cleversearch_admin_token");
            localStorage.removeItem("cleversearch_admin_refresh_token");
        }
    }).catch(() => {
        // 네트워크 오류 시에도 안전하게 정리 (다음 로그인 시 새로 발급)
        localStorage.removeItem("cleversearch_admin_token");
        localStorage.removeItem("cleversearch_admin_refresh_token");
    });
})();
```

**핵심 변경**:
- 토큰 존재만으로 `/admin` 으로 보내지 않음
- `/me` 응답이 200 일 때만 이동 → 실제 세션 유효성 보장
- 401 / 네트워크 오류 시 localStorage 토큰을 즉시 정리 → 무한루프 차단점 1

### 3.2 [static/admin/index.html](../static/admin/index.html) — 리다이렉트 직전 localStorage 정리

수정 후:
```js
function clearAdminLocalStorage() {
    // 로그인 화면이 토큰 존재만 보고 /admin 으로 자동 이동하지 않도록
    // 모든 인증 관련 localStorage 키를 한 번에 정리한다.
    localStorage.removeItem("cleversearch_admin_token");
    localStorage.removeItem("cleversearch_admin_refresh_token");
    localStorage.removeItem("cleversearch_admin_username");
    localStorage.removeItem("cleversearch_admin_role");
    localStorage.removeItem("cleversearch_admin_active_tab");
    localStorage.removeItem("cleversearch_admin_force_dashboard_once");
}

function forceLoginRedirect() {
    // 쿠키 인증이 무너진 상태에서 localStorage 토큰만 살아있으면
    // login.html 이 다시 /admin 으로 보내며 무한루프(화면 와리가리)가 발생한다.
    // 리다이렉트 직전에 잔존 localStorage 토큰을 모두 정리해서 차단한다.
    clearAdminLocalStorage();
    window.location.replace("/static/admin/login.html");
}

async function logoutJwt() {
    // ... (기존 logout API 호출 그대로)
    accessToken = "";
    refreshToken = "";
    loggedInUsername = "";
    loggedInRole = "viewer";
    clearAdminLocalStorage();   // ← 토큰까지 정리
    forceLoginRedirect();
}
```

**핵심 변경**:
- `clearAdminLocalStorage()` 헬퍼로 정리 항목을 한 곳에 모음
- `forceLoginRedirect()` 와 `logoutJwt()` 둘 다 토큰까지 정리 → 무한루프 차단점 2

## 4. 새 인증 플로우 (수정 후)

```
[정상 로그인 - 처음]
  사용자 ID/PW 입력
  → POST /api/v1/common/auth/login
    → 응답: access/refresh token (JSON) + Set-Cookie (cs_access_token, cs_refresh_token)
  → localStorage 저장 + window.location.replace("/admin#dashboard")

[/admin 진입]
  → initializeSession() : GET /me (쿠키 인증)
    ├─ 200 OK:    정상 진입, dashboard 로드
    └─ 401 Fail:  forceLoginRedirect()
                  ├─ clearAdminLocalStorage() ← localStorage 모두 비움
                  └─ window.location.replace("/static/admin/login.html")

[/static/admin/login.html 진입]
  → autoRedirectIfAuthenticated() :
      localStorage 에 token 있음? 
      ├─ 없음:   로그인 폼 표시
      └─ 있음:   GET /me 검증 (쿠키 인증)
                  ├─ 200 OK:  window.location.replace("/admin")
                  └─ 401/오류: localStorage token/refresh_token 제거 → 로그인 폼 표시
```

**핵심 보장**:
- 쿠키와 localStorage 가 어긋나도 한쪽 페이지에서 즉시 정리 → 다음 호출엔 일관된 상태
- 네트워크/서버 오류로 /me 가 실패해도 localStorage 가 정리되므로 깨끗한 로그인 화면에 멈춤

## 5. 기능 적용 이유

### 5.1 왜 토큰 존재만으로 리다이렉트하면 안 되는가
- localStorage 의 토큰은 만료 여부 / 폐기 여부 / 쿠키 동기화 여부를 알지 못한다
- 단순 존재 확인은 "유효성 검증" 이 아니라 "사용 가능성 추정" 일 뿐 → 어긋나는 모든 시점에 무한루프 발생
- `/me` 호출은 백엔드가 권위있게 판단하므로 안전한 분기점

### 5.2 왜 forceLoginRedirect 직전에 localStorage 를 비우는가
- 리다이렉트 직후 login.html 이 토큰 존재 검사를 다시 한다 (보통 1번 수정으로도 충분하지만, 방어선을 두 곳에 두면 어느 한쪽이 망가져도 방어됨)
- /me 호출 자체가 실패하는 네트워크 상황에서도 localStorage 가 비워지면 사용자가 명시적으로 다시 로그인할 수 있음
- "쿠키 죽음 + localStorage 살음" 이 잠재적 보안 단서가 될 수 있어 명시적 정리가 안전

### 5.3 왜 catch 블록도 localStorage 를 정리하는가
- 백엔드가 일시 다운 / DNS 오류 / 인증서 문제 등으로 fetch 자체가 실패할 수 있음
- 이때 토큰을 그대로 두면 사용자가 새로고침 시 "있어 보이는 토큰" 으로 다시 /admin 시도 → 같은 오류 반복
- 깨끗한 로그인 화면에서 사용자가 명시적으로 재시도할 수 있게 함

### 5.4 왜 logout 시에도 토큰까지 정리하는가
- 기존 코드는 `username`, `role`, `active_tab` 만 정리하고 핵심 토큰을 남김
- 이 상태에서 logout 다음에 /admin 진입 시 login.html 이 다시 토큰 보고 /admin 으로 보냄 (= 같은 무한루프)
- logout 의 의미상 모든 인증 흔적이 정리되어야 정합

### 5.5 왜 /me 호출에 cache: "no-store" 를 쓰는가
- 브라우저가 GET /me 를 캐시하면, 만료 후에도 캐시된 200 으로 잘못 통과될 수 있음
- 인증 상태 점검은 항상 실시간 서버 응답을 받아야 정합

## 6. 영향 범위

| 영역 | 영향 |
|---|---|
| 로그인 → /admin 정상 흐름 | 변화 없음 (200 OK 면 동일하게 이동) |
| 쿠키 유효 + 토큰 정상 케이스 | 변화 없음 |
| 쿠키 만료 + 토큰 잔존 케이스 | 무한루프 → 즉시 로그인 폼 표시로 변경 (수정 효과) |
| 네트워크 일시 오류 | 무한루프 → 로그인 폼 표시 (수정 효과) |
| 로그아웃 | 토큰까지 완전 정리되어 다음 진입 시 깨끗한 상태 |
| 백엔드 라우트 | 변경 없음 — 프론트엔드만 수정 |
| DB / 마이그레이션 | 변경 없음 |

## 7. 테스트 시나리오

1. **정상 로그인**
   - admin/admin123! 로 로그인 → /admin#dashboard 정상 표시
2. **쿠키 강제 만료 후 새로고침**
   - DevTools → Application → Cookies → cs_access_token 삭제 → /admin 새로고침
   - 기대: login.html 로 즉시 이동 + 로그인 폼 표시 (깜빡임 없음)
3. **localStorage 만 살아있고 쿠키 없음**
   - DevTools → Application → Cookies → 모두 삭제. localStorage 는 그대로
   - /admin 새로고침 → login.html 진입 시 /me 검증 → 401 → 로그인 폼 표시
4. **로그아웃 후 /admin 직접 입력**
   - 헤더의 로그아웃 → /admin URL 직접 입력 → login.html (토큰 모두 정리됨)
5. **네트워크 단절 시뮬레이션**
   - DevTools → Network → Offline → /admin 진입 → login.html 로 이동 (catch 분기로 정리됨)
