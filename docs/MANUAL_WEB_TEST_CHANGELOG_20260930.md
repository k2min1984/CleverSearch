## 요청과 산출물

사용자 요청: 두 프로젝트를 내일 웹에서 직접 전체 시험할 수 있도록, 무엇을 누르고 어떤 결과가 나와야 정상인지 시나리오를 작성.

- 시작 안내 1개, 프로젝트별 시나리오 2개, 빈 결과표 1개.
- CleverSearch 기본 62 + 조건부 8 = **70개**.
- CLEVERCHAT 기본 79 + 조건부 9 = **88개**.
- 합계 **158개**. 각 프로젝트의 현재 관리자 메뉴 전체를 대응표에 포함.
- 기존 5종 문서 사본, 신규/이름만 바꾼 Word 2개, 거절 확인용 3개, 폴더 수집용 1개: 파일 **11개**. JSON 출력용 빈 폴더 포함.
- 신규 파일을 서버에 미리 업로드하거나 내일의 시험 결과를 통과로 채우지 않음.

## 작성 파일 검증

`18-build-manual-test-checklist.py`로 아래 항목을 검사하고 `manual-scenario-document-check.json`에 남긴다.

- 시나리오 번호가 중복·누락 없이 순서대로 있는지.
- 모든 번호가 빈 결과표에 포함됐는지.
- MD의 로컬 문서 링크가 실제 파일을 가리키는지.
- 신규 Word를 python-docx로 읽을 수 있고 고유 검색어가 있는지.
- 이름만 다른 Word의 바이트가 같은지.
- 용량 초과 시험 파일은 정확히 31MiB, 빈 파일은 0바이트인지.

프로젝트 docs 사본은 중앙 원본과 해시를 비교한다. 이 검사는 **시험 문서와 준비 파일 확인**이며 158개 수동 기능을 미리 실행했다는 의미가 아니다.

## 실행 중 환경 이슈

- 제한 환경에서 프로젝트 `.venv` Python을 실행할 때 프로세스 생성이 차단됐다. 필요한 로컬 파일 준비 실행에 대해 `require_escalated` 자동 검토 허용 후 정상 완료했다. 프로그램 장애로 분류하지 않는다.
- PowerShell에 Python 한글 출력이 깨져 보이는 부분이 있어 최종 검사 출력은 ASCII JSON으로 정리했다. 디스크 파일명과 MD/Word의 UTF-8 내용은 별도 확인한다.
- 기존 미커밋 변경을 되돌리지 않았고, 새 DB 초기화·계정 변경·회사 서비스 연결·메일 발송은 수행하지 않았다.
