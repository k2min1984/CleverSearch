# SMB 크로스플랫폼 고도화 및 이력 관리 시스템 구축

- **작성일**: 2026-04-03
- **작성자**: 현승준

---

## 1. 개요

사내 파일 공유 서버(SMB/CIFS) 연동을 Windows 전용(`net use`)에서 크로스플랫폼(`smbprotocol`)으로 전환하고,
파일 변경 실시간 감지(watchfiles), 증분 색인, DB/OpenSearch 네트워크 모니터링 기능을 추가함.

## 3. 기능 상세

### 3.1 SMB 크로스플랫폼 전환 (1번 기능)

**기존**: Windows `net use` 명령으로만 SMB 접속 가능 (Linux/Docker 미지원)

**변경**: `smbprotocol` 라이브러리 기반 순수 Python SMB2/3 클라이언트

- `app/utils/smb_client.py`의 `SMBClient` 클래스
  - `connect()` / `disconnect()` — 세션 관리 (context manager 지원)
  - `walk()` — 공유 폴더 재귀 탐색 (확장자 필터)
  - `read_bytes()` — 파일 바이너리 읽기
  - `test_connection()` — 연결 테스트
- `SmbSource` 모델에 `domain` (도메인 인증), `port` (기본 445) 컬럼 추가
- API 스키마(`SmbSourceRequest`)에 `domain`, `port` 필드 추가

### 3.2 파일 변경 감지 및 증분 색인 (2번 기능)

#### 증분 색인

- `file_index_states` 테이블: 파일별 SHA-256 해시 + 크기 + 최종 색인 시각 저장
- `SMBService._is_changed()`: 이전 해시와 비교하여 변경 여부 판별
- `SMBService._update_index_state()`: 색인 성공 후 상태 갱신
- `sync_source(force_full=False)`: 기본 증분 모드, `force_full=True`이면 전체 재색인
- 응답에 `unchanged` 필드 추가 (해시 동일하여 스킵된 파일 수)

#### 실시간 파일 워처 (FileWatcherService)

- `watchfiles` 라이브러리로 파일시스템 이벤트 실시간 감지
- 활성 SMB 소스의 `share_path`를 자동 감시 대상으로 등록
- 이벤트 타입별 처리:
  - `created` / `modified` → 해시 비교 후 변경분만 색인 + `indexing_history` 기록
  - `deleted` → `indexing_history`에 삭제 이력 기록 + `file_index_states`에서 제거
- daemon 스레드로 백그라운드 실행

### 3.3 네트워크 모니터링 확장 (3번 기능)

#### NetworkMonitorService

- 30초 간격(설정 가능)으로 OpenSearch / 업무 DB 연결 상태 점검
- 상태 전이 감지:
  - 정상 → 단절: `disconnect` 이벤트 기록
  - 단절 → 복구: `reconnect_success` 이벤트 기록
- 서버 시작 시 자동 시작, 종료 시 자동 정리

| source_type | 점검 대상 | 점검 방식 |
|-------------|-----------|-----------|
| `opensearch` | OpenSearch 클러스터 | `client.info()` 호출 |
| `db` | 업무 PostgreSQL | `SELECT 1` 실행 |
| `smb` | SMB 공유 서버 | sync 시 자동 기록 (기존) |

## 4. 추가된 API 엔드포인트

### 4.1 SMB 관련 (기존 확장)

| Method | 경로 | 설명 |
|--------|------|------|
| POST | `/smb/sources/{id}/test` | SMB 연결 테스트 |
| GET | `/smb/sync-history` | 동기화 이력 조회 |
| POST | `/smb/sources/{id}/sync?force_full=true` | 전체 재색인 (기본 증분) |

### 4.2 색인 이력

| Method | 경로 | 설명 |
|--------|------|------|
| GET | `/indexing/history` | 색인 이력 조회 (필터: source_type, source_name, status) |
| DELETE | `/indexing/history?before_days=30` | 오래된 이력 정리 |

### 4.3 네트워크 이벤트 이력

| Method | 경로 | 설명 |
|--------|------|------|
| GET | `/network/events` | 네트워크 이벤트 조회 (필터: source_type, event_type) |
| DELETE | `/network/events?before_days=90` | 오래된 이벤트 정리 |

### 4.4 파일 워처

| Method | 경로 | 설명 |
|--------|------|------|
| POST | `/watcher/start` | 파일 변경 감지 워처 시작 |
| POST | `/watcher/stop` | 워처 중지 |
| GET | `/watcher/status` | 워처 상태 조회 |

### 4.5 네트워크 모니터

| Method | 경로 | 설명 |
|--------|------|------|
| POST | `/monitor/start?interval_seconds=30` | 네트워크 모니터 시작 |
| POST | `/monitor/stop` | 모니터 중지 |
| GET | `/monitor/status` | 모니터 상태 조회 |

> 위 엔드포인트는 v1(`/api/v1/system/`)과 admin(`/api/admin/system/`) 라우터 모두에 등록됨.

## 5. 추가된 DB 테이블

| 테이블 | 용도 |
|--------|------|
| `smb_sync_history` | SMB 동기화 실행 이력 (시작/종료시간, 소요시간, 성공/실패 건수, trigger_type) |
| `indexing_history` | 개별 파일 색인 이력 (source_type, action, status) |
| `network_event_logs` | 네트워크 단절/재연결 이벤트 (source_type, event_type, detail) |
| `file_index_states` | 파일별 색인 상태 (SHA-256 해시, 크기, 최종 색인 시각) |

## 6. 적용 방법

### 6.1 의존성 설치

```bash
pip install smbprotocol watchfiles
```

또는 requirements.txt 전체 설치:

```bash
pip install -r requirements.txt
```

### 6.2 DB 마이그레이션 실행

```bash
# 마이그레이션 상태 확인
alembic current

# 마이그레이션 적용
alembic upgrade head
```

적용되는 마이그레이션:
- `20260403_0005` — `smb_sync_history`, `indexing_history`, `network_event_logs` 테이블 생성 + `smb_sources`에 `domain`/`port` 컬럼 추가
- `20260403_0006` — `file_index_states` 테이블 생성

### 6.3 환경변수 설정 (선택)

`.env` 파일에 아래 항목 추가 가능 (기본값 있어 필수 아님):

```env
# SMB 연결 타임아웃 (초)
SMB_CONNECT_TIMEOUT=10
SMB_READ_TIMEOUT=30
```

### 6.4 서버 재시작

```bash
uvicorn app.main:app --reload
```

서버 시작 시 `NetworkMonitorService`가 자동으로 시작되어 DB/OpenSearch 연결 상태를 감시합니다.

### 6.5 기능 활성화

서버 시작 후 API로 기능을 제어합니다:

```bash
# 파일 워처 시작 (활성 SMB 소스의 share_path 자동 감시)
curl -X POST http://localhost:8000/api/v1/system/watcher/start

# 네트워크 모니터 상태 확인
curl http://localhost:8000/api/v1/system/monitor/status

# SMB 동기화 (증분 모드 — 변경된 파일만)
curl -X POST http://localhost:8000/api/v1/system/smb/sources/1/sync

# SMB 동기화 (전체 재색인)
curl -X POST "http://localhost:8000/api/v1/system/smb/sources/1/sync?force_full=true"

# 각종 이력 조회
curl http://localhost:8000/api/v1/system/smb/sync-history
curl http://localhost:8000/api/v1/system/indexing/history
curl http://localhost:8000/api/v1/system/network/events
```

### 6.6 기존 SMB 소스 등록 시 변경사항

기존 `share_path`, `username`, `password`에 더해 `domain`, `port` 필드가 추가됨:

```json
{
  "name": "부서공유",
  "share_path": "\\\\192.168.1.100\\shared",
  "username": "user01",
  "password": "pass1234",
  "domain": "CORP",
  "port": 445,
  "is_active": true
}
```

> `domain`과 `port`는 선택 항목이며, 미입력 시 각각 `""`, `445`가 기본값으로 적용됩니다.

## 7. Swagger UI CSP 수정

`/docs`, `/redoc`, `/openapi.json` 경로 접근 시 Swagger UI가 `cdn.jsdelivr.net`에서 JS/CSS를 로드하는데, 기존 CSP(Content-Security-Policy) 헤더에 해당 CDN이 허용되지 않아 페이지가 빈 화면으로 표시되는 문제를 수정하였습니다.

- Swagger/ReDoc 경로: `cdn.jsdelivr.net` 허용
- 기타 정적 페이지: 기존 `cdn.tailwindcss.com`/`cdnjs.cloudflare.com` 정책 유지

## 8. 참고사항

- `smbprotocol`은 SMB 2.0 / 2.1 / 3.0 / 3.1.1을 지원하며, NTLM + Kerberos 인증 가능
- `watchfiles`는 Rust 기반 고성능 파일 감시 라이브러리 (uvicorn reload에도 사용됨)
- 네트워크 모니터는 서버 시작 시 자동 실행되므로 별도 조작 불필요
- 파일 워처는 로컬 마운트된 경로에서만 동작 (SMB 네트워크 경로 직접 감시는 OS 마운트 필요)
