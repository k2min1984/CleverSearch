# 외부 에이전트(파일 감지 → 자동 색인) 작업 내용 및 사용법

작성일: 2026-04-28
작성자: 현승준

---

## 1. 작업 개요

### 1.1 목적
사용자 PC의 **특정 폴더에 신규 파일이 추가되면**, 외부 GUI 에이전트가 해당 파일을 감지하여 CleverSearch 색인 API 로 자동 전송하고 즉시 색인되도록 한다.

### 1.2 배경
- 기존: 관리자가 파일을 직접 업로드하거나 SMB/SSH 소스를 등록해 스케줄러로 색인
- 신규 요구: **로컬 PC 폴더에 파일이 떨어지면 즉시 자동 색인** + **단일 exe 배포**(설치 불필요)
- 같은 파일이 반복 색인되지 않도록 에이전트 측에서 **이미 보낸 파일 기록**으로 1차 차단

### 1.3 결과물
- 서버 측 신규 엔드포인트: `POST /api/v1/index/agent-notify`
- 에이전트 단일 exe: `agent/dist/CleverSearchAgent.exe` (약 13 MB)
- Python/설치 없이 더블클릭으로 실행 가능

## 2. 작업 내용

### 2.1 서버 측 변경

| 파일 | 변경 내용 |
|---|---|
| [app/core/config.py](../app/core/config.py) | `AGENT_API_KEY` 환경변수 추가 (빈 값이면 엔드포인트 비활성) |
| [app/api/v1/index.py](../app/api/v1/index.py) | `POST /api/v1/index/agent-notify` 엔드포인트 추가 |

**엔드포인트 사양**

```
POST /api/v1/index/agent-notify
Headers:
  X-Agent-Key: <서버에 설정한 AGENT_API_KEY 값>
Body (multipart/form-data):
  file:        UploadFile (필수, 감지된 파일 바이너리)
  source_path: str        (선택, 에이전트 측 절대 경로 - 추적용)
```

**처리 흐름**
1. `X-Agent-Key` 헤더 검증 → 불일치 시 **401**
2. 파일 크기 검증 (최대 100MB) → 초과 시 **413**
3. SHA-256 해시로 DB 중복 차단 (동일 파일 빠른 컷)
4. 통과 시 `IndexingService.index_bytes()` 호출 → **기존 업로드 경로와 100% 동일한 색인 파이프라인** 실행
5. 결과 JSON 반환 (`status`, `message`, `file`, `content_hash`, `category`, `doc_id` 등)

### 2.2 에이전트 신규 생성 (`agent/`)

| 파일 | 역할 |
|---|---|
| [agent/main.py](../agent/main.py) | Tkinter GUI 진입점 (API 설정 / 폴더 목록 / 시작·중지 / 로그) |
| [agent/config.py](../agent/config.py) | `%APPDATA%\CleverSearchAgent\config.json` 로드/저장 |

| [agent/watcher.py](../agent/watcher.py) | watchdog 폴더 감시 + 파일 안정화 대기 + 시작 시 기존 파일 스캔 |

## 3. 아키텍처

### 3.1 전체 구성도

```
+--------------------------------------+              +------------------------------+
|  사용자 PC (CleverSearchAgent.exe)   |              |   CleverSearch Server        |
|                                      |              |                              |
|  [Tkinter GUI]                       |              |   /api/v1/index/agent-notify |
|     |                                |  multipart   |          |                   |
|  [FolderWatcher (watchdog)]  ----->  |  POST + Key  |   X-Agent-Key 검증           |
|     |                                |              |          |                   |
|  [FileRegistry]                      |              |   DB 해시 중복 차단          |
|   (registered_files.txt)             |              |          |                   |
|     |                                |              |   IndexingService.           |
|  [CleverSearchClient (httpx)]        |              |       index_bytes()          |
|                                      |              |          |                   |
|                                      |              |   OpenSearch 색인            |
+--------------------------------------+              +------------------------------+
```

### 3.2 신규 파일 처리 흐름

1. watchdog 이 `on_created` / `on_moved` 이벤트 캡처 → 큐에 적재
2. 워커 스레드가 큐에서 꺼내 **파일 크기 안정화** 대기 (기본 2초간 변동 없음 검증 - 쓰기 완료 보장)
3. 파일 키 생성: `{경로}|{크기}|{mtime}|{앞 64KB sha1}`
4. `registered_files.txt` 의 set 캐시에 키가 있으면 **조용히 스킵**
5. 없으면 multipart 업로드 → 서버 응답 수신
6. `status` 가 `success` 또는 `skipped` 면 키를 텍스트DB 에 추가 → 동일 파일 재전송 영구 차단

### 3.3 이중 중복 차단 구조

| 단계 | 위치 | 키 | 효과 |
|---|---|---|---|
| 1차 | 에이전트 텍스트DB | 경로+크기+mtime+sha1 | 네트워크 호출 자체를 안 함 |
| 2차 | 서버 진입부 | 파일 바이트 SHA-256 (DB) | 색인 파싱 비용 절감 |
| 3차 | IndexingService 내부 | 텍스트 해시 + DB 제목/내용 | OpenSearch 색인 직전 최종 검증 |

## 4. 사용법

### 4.1 서버 측 준비

#### A. API Key 발급
**API Key 는 본인이 정하는 비밀 문자열**입니다 (외부에서 받아오는 게 아님).

**랜덤 키 생성 방법 (권장)**

```bash
# Python
python -c "import secrets; print(secrets.token_urlsafe(32))"

# PowerShell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))

# Git Bash / Linux
openssl rand -base64 32
```

→ 출력된 랜덤 문자열을 사용 (최소 16자, 32자 이상 권장)

#### B. 서버 `.env` 설정

프로젝트 루트의 `.env` 파일에 추가:

```env
AGENT_API_KEY=여기에_생성한_랜덤_키_붙여넣기
```

> ⚠️ **빈 값이면 엔드포인트가 비활성화**됩니다 (503 응답).

#### C. 서버 재기동
환경변수가 적용되도록 CleverSearch 서버를 재기동합니다.

### 4.2 에이전트 설치 (PC 측)

#### 옵션 A: 빌드된 exe 사용 (권장)
1. `agent/dist/CleverSearchAgent.exe` 파일을 사용자 PC 의 원하는 폴더에 복사
2. 더블클릭으로 실행 (Python, 설치 모두 불필요)

> 첫 실행 시 Windows SmartScreen 경고 → "추가 정보 → 실행" 클릭

#### 옵션 B: 개발 모드 실행
```bash
cd agent
pip install -r requirements.txt
python main.py
```

#### 옵션 C: 직접 빌드
```bash
cd agent
build.bat
# → agent/dist/CleverSearchAgent.exe 생성
```

### 4.3 에이전트 GUI 사용법

| 영역 | 입력값 |
|---|---|
| **API URL** | `https://<서버주소>:8000/api/v1/index/agent-notify` |
| **API Key** | 서버 `.env` 의 `AGENT_API_KEY` 와 **동일한 값** |
| **SSL 인증서 검증** | 자체서명 인증서면 **체크 해제** / 정식 인증서면 체크 |
| **감시 폴더** | "폴더 추가" 버튼으로 1개 이상 등록 |
| **확장자** | 색인 대상 확장자 (콤마 구분, 기본: pdf, hwp, hwpx, docx, pptx, xlsx, xls, jpg, jpeg, png, txt) |

**버튼**
- **감시 시작 / 중지**: 토글. 시작 시 자동으로 폴더 전체를 1회 스캔 (미등록 파일도 색인)
- **설정 저장**: 현재 입력값을 `config.json` 에 저장
- **등록 기록 초기화**: `registered_files.txt` 삭제 → 다음 시작 시 폴더 내 모든 파일이 재색인 요청됨

**로그 영역**: 감지/전송/결과가 실시간 표시
```
[16:52:31] 감시 시작
[16:52:48] 감지 -> 회의록.pdf (245.3 KB)
[16:52:50]   [OK] success: 색인 완료
[16:53:12] 감지 -> 보고서.docx (1024.8 KB)
[16:53:13]   [OK] skipped: DB 중복(동일 파일): 보고서.docx
```

### 4.4 설정/기록 파일 위치

```
%APPDATA%\CleverSearchAgent\
  ├ config.json              ← API URL/Key, 폴더 목록, 확장자
  └ registered_files.txt     ← 이미 색인 요청된 파일 키 (한 줄당 1건)
```

> 사용자별로 분리되며 exe 와 같은 위치가 아니므로, exe 를 다른 PC 로 옮겨도 설정은 따라가지 않습니다 (의도된 동작).

## 5. 운영 가이드

### 5.1 다른 PC 에 배포
1. `CleverSearchAgent.exe` 파일 1개만 복사 (Python 미설치 PC 도 OK)
2. 첫 실행 시 GUI 에서 API URL / Key / 감시 폴더 입력 후 "감시 시작"

### 5.2 자동 시작 (선택)
Windows 시작 시 자동 실행하려면:
- `Win + R` → `shell:startup` 실행 → 열린 폴더에 exe 의 **바로가기** 생성
- 또는 작업 스케줄러에 등록

### 5.3 보안 주의사항
- **HTTPS 필수**: HTTP 사용 시 API Key 가 평문으로 흐름
- **키 유출 시**: 서버 `.env` 의 키 교체 → 서버 재기동 → 모든 에이전트 GUI 에 신규 키 재입력
- **GitHub commit 금지**: `.env` 는 `.gitignore` 에 포함되어야 함
- **Defender/백신**: 일부 환경에서 PyInstaller 산출물을 임시격리할 수 있음 → 사내 화이트리스트 등록 권장
- **코드사이닝**: 정식 배포 시 인증서로 서명하면 SmartScreen 경고 제거

### 5.4 트러블슈팅

| 증상 | 원인 / 조치 |
|---|---|
| `401 유효하지 않은 에이전트 키` | 서버 `.env` 와 GUI 의 API Key 가 다름 → 동일하게 맞추고 서버 재기동 |
| `503 AGENT_API_KEY 미설정` | 서버 `.env` 에 `AGENT_API_KEY` 없음 또는 빈 값 → 설정 후 재기동 |
| `네트워크 오류` | URL 오타 / 방화벽 / SSL 인증서 → 자체서명이면 "SSL 인증서 검증" 체크 해제 |
| 파일이 감지되지 않음 | 확장자가 화이트리스트에 없거나, 파일이 아직 쓰기 중 → 안정화 대기 후 자동 처리 |
| 같은 파일이 계속 무시됨 | `registered_files.txt` 에 이미 등록 → "등록 기록 초기화" 버튼으로 리셋 |
| `413 파일 크기 초과` | 100MB 초과 → 분할 업로드 또는 서버 측 `AGENT_MAX_UPLOAD_SIZE` 상향 |
| 빌드 실패 (`pyinstaller not found`) | `pip install pyinstaller` 또는 `python -m PyInstaller ...` 사용 |

### 5.5 확장 포인트 (향후)
- 다중 API Key (에이전트별 식별)
- 트레이 아이콘 모드 (창 닫아도 백그라운드 유지)
- 파일 삭제/이동 이벤트 → 색인 동기 삭제
- 전송 실패 시 큐 재시도 + 영구 보관
- 코드사이닝 인증서 적용
